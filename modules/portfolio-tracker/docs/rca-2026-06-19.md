## Critical Anomalies (3)

### A1. Opaque HTTP 500 error handler — no diagnostic information

**Severity:** CRITICAL
**File:** `src/mcp-server.js:234-244`

```js
} catch (e) {
    console.error(JSON.stringify({ event: "mcp_error", error: e.message }));
    if (!res.headersSent)
        res.status(500).json({
            jsonrpc: "2.0",
            error: { code: -32603, message: "Internal server error" },
            id: null,
        });
}
```

Every MCP transport failure, session corruption, parse error, or upstream failure surfaces identically as HTTP 500 with the hardcoded string `"Internal server error"`. The real error IS logged to `console.error` (line 236) but zero diagnostic information reaches the client. The `!res.headersSent` guard (line 238) means if the MCP SDK already sent headers before throwing, the error is silently swallowed — causing client timeouts indistinguishable from 500s.

**Suggested fix:** Differentiate error types — return 400 for session errors, 502 for dead transport, 500 only for truly internal errors. Include `e.message` in the JSON-RPC error detail (`.data` field). Use distinct JSON-RPC error codes per failure mode.

### A2. Hardcoded Docker hostnames — no DNS resilience

**Severity:** CRITICAL
**File:** `src/tools.js:626,719`

```js
// tools.js:625-626 — _notifyUser
const gatewayUrl = process.env.OPENCLAW_GATEWAY_URL || "http://openclaw:18800";

// tools.js:719 — fetchBudget
const url = `http://actual-api:3000/budget-12m?budget_id=...`;
```

Six external hostnames are resolved at call time via the Docker embedded DNS resolver. When the resolver fails, every call site fails simultaneously. Retry logic exists only on budget fetch (`tools.js:720-748`, 3 attempts, no jitter) and token refresh (`onedrive.js:36-53`, 3 attempts). All retries re-resolve the same broken hostname — ineffective against DNS outages. Notifications (`tools.js:633-652`) and FX rates (`tools.js:1006-1033`) have no retry at all.

**Affected hostnames:**

| Hostname | Location | Operation |
|---|---|---|
| `openclaw` | tools.js:626 | User notification via gateway |
| `actual-api` | tools.js:719 | Budget data fetch |
| `login.microsoftonline.com` | onedrive.js:38, onedrive_oauth.js:61 | OAuth token refresh |
| `open.er-api.com` | tools.js:1007 | Live FX rates |
| `ndcdyn.interactivebrokers.com` | ibkr_flex.js:13 | IBKR flex queries |
| `graph.microsoft.com` | onedrive.js:72,91,161 | OneDrive file ops |

**Suggested fix:** Add DNS resolution health-check at startup. Use Node.js `dns.resolve()` with TTL caching. Add short-lived in-memory IP cache. Add IP-level fallback via `--add-host` for critical inter-container communication.

### A3. Unbounded transport map — sessions never expire

**Severity:** CRITICAL
**File:** `src/mcp-server.js:204-231`

```js
const transports = {};   // line 204 — never pruned except on explicit .onclose

if (sessionId && transports[sessionId]) {
    transport = transports[sessionId];  // lines 211-212 — reused blindly, zero health check
}

transport.onclose = () => {            // lines 227-230
    const sid = transport.sessionId;
    if (sid) delete transports[sid];   // ONLY cleanup path
};
```

The `transports` map stores `StreamableHTTPServerTransport` objects keyed by session ID. Transport reuse (line 212) has zero liveness check. Cleanup exists only on `transport.onclose` (line 227), which fires only on clean client disconnect. Container restarts, network partitions, or TCP timeouts kill transports silently — `onclose` never fires, the dead transport stays in the map, and every subsequent request with that session ID fails identically with HTTP 500 (A1).

**Why frequent:** Each cron-triggered sync creates a new MCP session → new transport. Over hours, the `transports` map accumulates dead entries. Prior analysis found 42 session re-registrations in 8 hours (~5.25/hour).

**Suggested fix:** Add 10-minute idle TTL to transport entries with `setTimeout` cleanup. Before reusing a transport, check its state. If dead, remove from map and create new. Return 400 "session expired" so the client can retry without a session ID.

## High-Priority Anomalies (3)

### A4. Retry storms with no jitter, no circuit breaker

**File:** `src/tools.js:720-748`

```js
for (let attempt = 0; attempt < maxRetries; attempt++) {
    // ...
    await sleep(2 ** attempt * 1000);  // 1s, 2s, 4s — NO jitter
}
```

Retry delays are deterministic and identical across containers. Both portfolio-tracker and expense-tracker cron jobs hit `actual-api` simultaneously — thundering herd. No circuit breaker: retries continue even when the API returns 5xx consistently.

**Suggested fix:** `sleep((2**attempt + Math.random()) * 1000)`. Add circuit breaker: skip remaining retries if API returns 5xx on first attempt. Stagger cron schedules by 30s between containers.

### A5. Dead transports reused blindly

**File:** `src/mcp-server.js:211-212` — same root cause as A3. Listed separately because the immediate symptom (connection loss mid-session) differs from the systemic leak.

**Suggested fix:** Same as A3.

### A6. Sync output unbounded — full holdings + taxonomy in response

**File:** `src/tools.js:836-845`, `src/mcp-server.js:15-75`

`_computeSyncAll` return object includes full holdings arrays and taxonomy data. `formatSyncResult` builds a text summary that includes all this data. Response size grows linearly with portfolio size with no truncation.

**Suggested fix:** Cap sync response at 16KB. Limit holdings to top 10 entries. Omit raw `flex_import` data from response.

## Critical Test Gaps (4)

### G1. `src/index.js` — zero coverage (259 lines)

**Root cause:** `src/index.js:48` — `guardEnv()` at module import time.

```js
// index.js:21-48
function guardEnv() {
    const critical = [
        "DEEPSEEK_API_KEY", "ACTUAL_BUDGET_URL", "ACTUAL_BUDGET_PASSWORD",
        "ACTUAL_PRIMARY_BUDGET_FILE", "ACTUAL_SECONDARY_BUDGET_FILE",
        "ONEDRIVE_CLIENT_ID", "IBKR_FLEX_TOKEN", "IBKR_FLEX_QUERY_ID",
        "IBKR_PP_SGD_ACCOUNT", "IBKR_PP_USD_ACCOUNT",
        "GOOGLE_SERVICE_ACCOUNT_JSON", "GOOGLE_SHEET_ID",
    ];
    const missing = critical.filter((k) => !process.env[k]);
    if (missing.length > 0) { /* ... */ process.exit(1); }
}
guardEnv();  // RUNS AT PARSE TIME — blocks any import
```

ANY `import` of index.js triggers immediate `process.exit(1)` unless all 12 env vars are set. Test runners cannot even load the module. Additionally, `main()` (lines 50-259) is a monolith: constructs all dependencies inline, creates Express app, registers 19 routes, creates MCP server, starts IMAP idle loop — zero injection seams.

**Suggested fix:** Move `guardEnv()` inside `main()`. Split into critical (process.exit) vs. optional (warn) tiers. Extract route registration, IMAP startup, MCP creation into injectable functions.

### G2. `src/mcp-server.js` — string-assertion tests only (283 lines)

**Root cause:** `tests/mcp-server.test.js` never calls `createMcpServer()`, never instantiates `StreamableHTTPServerTransport`, never tests session creation/reuse/cleanup. Tests only check string equality on error message constants.

**Suggested fix:** Create integration test that starts real Express server with `createMcpServer`, sends HTTP requests to `/mcp`, asserts session creation/reuse/tool responses. Or refactor to accept mock transport factory.

### G3. `src/ibkr_flex.js` — zero coverage (114 lines)

**Root cause:** `src/ibkr_flex.js:38` — direct `fetch()` to IBKR.

```js
const resp = await fetch(`${IBKR_SEND_URL}?${params}`, { ... });
```

Reads credentials from `process.env`, uses `AbortSignal.timeout(30000)`, parses XML with regex — all tightly coupled. Zero injection seams.

**Suggested fix:** Accept optional `httpClient` parameter. Extract XML parsing into separate `parseFlexResponse(text)`. Move CLI mode to separate file.

### G4. `src/onedrive_oauth.js` — zero coverage (84 lines)

**Root cause:** `src/onedrive_oauth.js:61,80-81` — direct `fetch()` + filesystem writes.

```js
const resp = await fetch(TOKEN_URL, { ... });               // line 61
if (!existsSync(dir)) mkdirSync(dir, { recursive: true });   // line 80
writeFileSync(tokenPath, data.refresh_token);                // line 81
```

HTTP calls, filesystem writes, and env-var reads all directly in `exchangeCodeForToken()`. No injectable dependencies.

**Suggested fix:** Accept optional `httpClient` and token storage interface as parameters. Test URL construction, code extraction, and error handling with mock HTTP responses.

## Cross-Cutting Architectural Root Causes

### Pattern 1: Zero abstraction over external I/O

**Affected files:** ibkr_flex.js, onedrive_oauth.js, tools.js (_fetchLiveRates, _notifyUser, _computeSyncAll), onedrive.js, mcp-server.js, java_bridge.js (_runCommand)

Every source file calls `fetch()` or `spawn()` directly without an injectable HTTP/process layer. This makes anomaly debugging impossible (cannot replay failures), testing impossible (cannot mock network without global monkey-patching), and DNS resilience impossible (must change every call site).

### Pattern 2: Tight coupling at module import time

**Affected files:** index.js (guardEnv at line 48), email_handler.js (dynamic import of mailparser)

Side effects at import time prevent test runners from even loading the module. `guardEnv()` at `index.js:48` runs before any test can set up environment variables.

### Pattern 3: Monolithic functions with no injection seams

**Affected files:** tools.js (_computeSyncAll at 189 lines, _dispatch at 162 lines), orchestrator.js (processEmail at 117 lines), index.js (main at 210 lines)

Large functions orchestrate 5+ service calls in sequence with no injection points. Each function is a single indivisible unit — either fully works or fully fails, with no intermediate states and no partial testing.

### Pattern 4: Double-layer opaque error handling

**Affected files:** mcp-server.js (MCP path) vs index.js (Express path)

Two different error paths for the same tool execution: MCP errors are always `"Internal server error"` (unactionable), while REST errors include the real `e.message` (actionable). This inconsistency silently conceals failures from MCP users.

## Prioritized Corrective Actions

### Immediate (CRITICAL)

1. **Add error differentiation to MCP handler** (`src/mcp-server.js:234-244`) — return specific HTTP statuses (400/502/500) and include `e.message` in JSON-RPC error.data. Fixes A1, A3, A5 simultaneously.
2. **Add transport TTL and liveness checks** (`src/mcp-server.js:204,211`) — 10-minute idle timeout, dead transport removal, return 400 "session expired". Fixes A3, A5.
3. **Move guardEnv() inside main()** (`src/index.js:48`) — split into critical vs. optional tiers. Fixes G1, enables testing of index.js.

### Short-term (HIGH)

4. **Create HTTP abstraction layer** — `HttpClient` class with retry, circuit breaker, DNS caching. Inject into ibkr_flex.js, onedrive_oauth.js, tools.js, onedrive.js. Fixes A2, G3, G4.
5. **Add jitter to all retry loops** — `sleep((2**attempt + Math.random()) * 1000)` in tools.js and onedrive.js. Fixes A4.
6. **Truncate sync output** — cap at 16KB, limit holdings to top 10. Fixes A6.
7. **Add sync-level mutex** — prevent concurrent `_computeSyncAll` runs. Fixes cron overlap race.

### Medium-term (MEDIUM)

8. Refactor index.js for testability — extract route registration, IMAP startup, MCP server creation.
9. Build test fixtures and fakes — canned IBKR XML, OneDrive JSON, AB budget JSON. In-memory Java bridge test double.
10. Create `TestHarness` wiring all fakes for integration tests. Fixes G13 (no integration tests).
11. Extract pure computation from I/O methods — `convertToSgd(currencies, rates)`, `parseFlexResponse(text)`.
12. Test error notification paths — mock orchestrator failure, assert notify_user is called.

### Long-term (LOW)

13. Parameterize `cleanText()` tests for boundary cases (signature detection, truncation, newline collapse).
14. Test IMAP reconnect logic with mocked connection drops.
15. Add snapshot tests for tool error response shapes (REST vs MCP consistency).
16. Enable SQLite WAL mode for dedup DB, add mutex.
17. Stagger cron schedules between containers by 30s.

## Dominant Finding

**The opaque MCP error handler (`mcp-server.js:234-244`) is the single most impactful code issue.** It directly causes or aggravates 3 of 7 log anomalies and makes debugging any MCP-path failure impossible. Every "HTTP 500" in the logs is a missed opportunity to diagnose the real problem. Fixing this one handler would provide immediate diagnostic value across the entire system.

**The lack of I/O abstraction is the single most impactful architectural issue.** It prevents testing in 8 source files, blocks DNS resilience improvements, and forces every retry/failover/health-check fix to be duplicated across every call site instead of centralized in one HTTP client layer.
